# 报告文本一致性工作台产品需求

## 目标与用户任务

目标操作人是报告撰写者或审核者，在提交前比对“影像所见”和“诊断意见”，核对差异证据并自行修改。当前使用合成文本验证该任务流程。

需求来自行业场景观察和假设，未开展正式医生访谈；不能据个人演示证明医院需要或愿意采购。

## 第一版优先级

必须项是三类规则、两处原文证据、覆盖和跳过说明、人工修改复检。随后补反馈、导出、会话管理与评测入口。AI是主动追加的语义候选复核，不替代规则或人工审核。账号、支付、医院接口、危急值与全病种分级不纳入本版。

| 模块 | 支持条件 | 不支持时 |
|---|---|---|
| 左右 | 明确位置、同类单对象、可唯一配对 | 否定、不确定、多对象或明确历史/时间片段不猜配对 |
| 尺寸 | 同侧同位置同对象、普通直径或无轴限定的精确单值mm/cm/毫米/厘米 | 约值、范围、多径、历史、缺值、最大/最小/长短径等口径及特殊数字格式不强比 |
| 肯否 | 同侧同位置同对象、明确存在与否定 | 稳定性不当不存在，复杂否定和明确历史/时间片段不强判 |
| AI语义 | 明确文本不一致候选、合法类别、两段可唯一定位原文 | 未提出候选、无法判断、非法输出和失败分别显示 |

## 使用流程

选合成案例或输入两段文本→选规则→开始检查→看原文与覆盖→必要时主动追加AI→人工修改→重新检查→反馈→导出。AI可能有费用，默认不开启，不输入真实患者资料。

## 数据和状态

一次检查有run_id、输入快照、规则范围、版本与提示列表。每条提示有id、类别、证据与区间、来源；反馈按id关联。追加AI更新同一次检查，不新增历史运行；同题合并保留规则id和反馈，两路来源不等于医学确认。

内容判断、执行状态和来源分开：模型无候选不反驳规则；失败不伪装通过；模拟与真实调用分开。编辑后旧响应最多补到旧记录，不覆盖新文本。比较前后提示数时，规则范围和AI完成模式必须一致。

AI独有新增候选统一归其他语义候选，标题明确“类别待核对”，保留模型原类别和未确认标记。与规则同类别、同区间的严格合并仍保留规则类别。此为避免未经验证分类误导人的产品策略，不代表自动判断类别正确。

输入来源按sample_id与原始样例逐字比较，改写标“已修改”；还原文本只恢复题名，不恢复旧结果/反馈。task_id跨同一任务修改保持，载入新样例/清空开启新任务。前后提示数比较另要求相同非空task_id、相同非空规则版本；缺失或不同不把差异当改正收益。

## 验收示例

同一对象6mm与0.6cm不提示；6mm与16mm提示核对；6×4mm不当单值；同位置多个结节不按尺寸猜对应；未见与可见只在同对象同侧比较。无可靠比较内容说明跳过，不能说整份报告正确。反馈不自动改报告；修改必须重新检查。

v1.3.1新增边界：去年左侧与今年右侧不当左右写反；三枚/数枚及同类模糊片段阻断猜配；最大径8mm与最小径18mm不强比，0,8cm不截为8cm。普通直径8mm与18mm仍提示。这里只拒绝已识别的有限模板，不声称理解所有历史、数量或测量语义。
