# AI技术选型与范围说明

## 当前结论

本项目检查报告撰写者已经提供的“影像所见”和“诊断意见”，寻找有限范围内的文本不一致。当前方案是确定性规则先检查；用户需要时，再对同一任务发起一次可选的大模型复核；系统校验候选和原文证据后，以保守方式合并结果，最终交由人工核对。

当前版本没有实现RAG、Agent或模型微调。这不是因为这些方法没有价值，而是因为它们解决的问题与当前已验证的任务不相同。以下判断说明现有依据、未满足的条件和未来重新评估的方式。

## 三种方法解决不同问题

| 方法 | 主要解决的问题 | 当前是否使用 | 本项目重新评估的条件 |
| --- | --- | --- | --- |
| RAG 检索增强生成 | 回答时需要查阅一组外部、持续维护的资料，并指出依据 | 否。当前比较依据来自同一任务里的两段文本，普通规则说明也可直接读取；项目没有经确认可用的医学知识库 | 产品确实需要解释某条规则来源时，先确定资料来源、版本、更新责任与授权方式，再用小规模资料测试召回和引用是否可靠。检索结果只用于解释资料依据，不据此判定哪段报告在医学上正确 |
| Agent 智能体 | 模型需要根据目标自行选择多个步骤或工具，并根据中间结果调整后续动作 | 否。当前步骤固定：规则检查、可选的一次模型复核、输出校验、结果合并、人工核对。普通API调用不等于Agent | 只有出现无法预先固定的多步任务或多系统操作需求时再评估；需要先限定可调用工具、权限、最大步骤、失败处理、日志和人工接管，并与固定工作流比较效果和成本 |
| 模型微调 | 用有代表性的示例调整模型对特定任务的输出习惯或分类表现 | 否。当前只有合成开发案例，没有经领域人员标注、授权并覆盖真实变化的训练集，也没有证据表明提示词和规则已到质量上限 | 先积累有权使用、去标识化、代表真实任务的标注数据；建立训练集与独立留出集；证明同类错误反复出现且规则或提示词难以解决；再比较微调前后的分类质量、误报漏报、成本和维护代价 |

## 为什么当前方案匹配任务

第一，当前任务是“比较这次输入中的两段文字”。它通常不缺外部知识。左右、精确尺寸换算和有限肯否表达可用规则复现，方便说明何时比较、何时跳过；复杂表达才由可选模型提出候选。把医学知识检索加入比较链，可能让“找到相关资料”被误解成“判断报告正确”，而本产品没有影像证据或临床裁决能力。

第二，操作路径可以预先写清楚。规则先执行；用户确认后最多做一次模型复核；程序检查输出格式、类别和原文证据；规则结果不会因模型失败或没有候选而消失。让模型自主规划和调用多个工具，会增加状态、权限、失败分支和追踪成本，却没有已证实的额外用户价值。

第三，目前的模型样本只用于开发对照，且来源为合成例。2026年10月20日的数量案例中，模型找到了“一枚”和“三枚”的差异，却误分为肯否冲突。这个结果支持保留分类不确定状态并要求人工核对；它不足以支持微调，也不能说明模型在真实医院报告上的错误分布。

## 再引入前要补齐什么

若未来考虑RAG，产品先写清“用户需要查什么、为什么不能直接展示规则说明、资料由谁维护”；研发再选资料切分、检索和引用实现；测试准备有标准答案的问题集，检查相关资料是否找全、出处是否正确、资料过期时能否拒答。若没有可维护资料或用户任务，先不建库。

若未来考虑Agent，产品先画出哪些决定确实需要动态选择；研发定义允许的动作和权限，并为每一步保留状态与日志；测试覆盖工具失败、超时、重复执行、越权和转人工。若流程始终是固定顺序，普通工作流更容易控制。

若未来考虑微调，产品和领域人员先定义错误标签和质量指标；数据负责人确认使用权限、去标识化和标注规范；研发建立可复现训练与版本管理；测试用独立留出数据比较基线。没有可靠标注和留出评测时，训练损失下降不能证明产品表现改善。

因此当前顺序是先验证输入范围、规则跳过策略、AI候选分类和人工复核体验；出现稳定且可量化的缺口后，选择解决该缺口的方法。技术是否采用由需求、数据和评测结果决定，不以技术名称的数量衡量产品完整度。
