# 影像知识助手 RAG 与 Agent 需求与验收

> 版本v0.1，2026-10-22。本地检索、限定PubMed查询、RAG/Agent服务端及页面已实现；12项新增定向测试、3项原接口回归、桌面/窄屏操作已通过。真实DeepSeek有限验收：一次格式失败安全拦截；明确JSON格式后，一条RAG合成问题生成带K4引用回答；一条Agent选择PubMed工具并返回2条目录。没有专家审核或外部用户验证，不能据此宣称医学准确性。

## 1. 产品目标

在现有“报告文本一致性检查”之外，增加一个独立的影像知识查询任务：影像科医生遇到术语、指南或专业知识问题时，可以向助手提问；助手只在经审核、允许使用的专业资料范围内检索，基于检索证据回答并展示出处。没有充分依据时应说明未找到可靠依据，而不是自由发挥。

知识助手不改变报告质控结论，不判断患者影像，不替代诊断、治疗、危急值处置或报告签发。两个任务在页面和日志中应可区分，避免用户把知识解释误认为对当前报告的医学裁决。

## 2. 用户故事与问题边界

**用户故事：**作为影像科医生，我希望针对一个专业问题查询被允许使用的专业资料，并看到回答对应的出处和原文依据；如果资料不足或互相矛盾，我希望助手明确告诉我，而不是猜测。

第一版问题类型：

- 专业术语或缩写的含义查询；
- 当前教材选段中分析方法和影像术语的定位与摘要；
- 已选中资料段落的解释与出处回看。

首批语料是Springer 2025年教材的两章、7个选段，覆盖局灶性肺病分析、次级肺小叶、微结节分布、树芽征和MIP等少量问题。每段有英文原句及中文AI整理摘要。检索使用BM25与中英术语匹配，未使用语义向量模型或向量数据库。在线检索仅通过NCBI E-utilities查PubMed目录，最多5项，返回作者、期刊、日期和原始链接。

第一版不处理：针对真实患者的诊断和治疗建议、图像判读、危急值处置、自动修改/签发报告、无来源的开放式医学问答。患者信息和治疗请求的有限模式拦截已实现，但它不是完整的医学意图识别系统。

## 3. 产品工作流

```text
用户输入问题
  → 意图与范围判断
  → 在授权来源目录中检索
  → 评估证据相关性、版本和充分性
      ├─ 证据充分：生成有出处的回答
      ├─ 问题含糊：先向用户澄清
      ├─ 结果偏弱但可调整：允许一次受控查询改写并重查
      └─ 无资料/来源冲突/仍不充分：拒答或提示人工查阅
  → 校验引用与回答主张的对应关系
  → 展示回答、引用、证据片段及资料时间/版本
```

### 为什么同时有 RAG 和 Agent

- **RAG**负责从允许使用的知识资料中找出与问题相关的证据，再把证据提供给模型组织回答。它解决“依据在哪儿”，不自动保证回答正确。
- **Agent**负责在边界内选择下一步动作，例如直接检索、要求补充问题、有限改写后重查，或因证据不足而停止。Agent 解决“接下来做什么”，不是给模型无限权限。
- 知识助手中两者协作；报告文本比较主链仍按固定的规则和可选模型流程运行，不因新增助手改造成自主Agent。

## 4. 功能范围

| 能力 | 第一版要求 | 暂不做 |
|---|---|---|
| 来源范围 | 仅允许目录内的来源/接口/域名；在页面说明当前可查资料范围 | 任意网页搜索、开放搜索结果自动纳入知识库 |
| 检索 | 先形成带元数据的资料目录；根据评测选择关键词、混合或向量检索 | 未评测就承诺“全面检索所有专业资料” |
| Agent 动作 | 受限意图判断、检索工具调用、一次有限重查、澄清或停止 | 自主调用任意网页、无限循环、多Agent协作、患者级处置 |
| 回答 | 基于证据摘要；每条关键结论显示来源、日期/版本、章节/页码/段落与链接 | 无引用的确定性医学结论、把资料结论直接套用于患者 |
| 拒答 | 无命中、相关性低、资料冲突或问题越界时说明原因 | 用模型参数记忆兜底填空 |
| 留痕 | 记录问题、检索来源ID、文档版本、Agent动作、引用、状态和耗时；不记录Key | 保存患者身份信息或将查询日志用于未经说明的训练 |

## 5. 资料治理与合规输入

资料入库前由产品/资料负责人确认来源权威性、适用范围、发布日期、有效版本、许可和更新责任。正式指南/共识、专业机构公开资料、允许使用的开放获取内容可作为候选；教材、付费期刊全文不能因为“专业”就默认可以下载、索引、保存或展示。

每份资料的最小元数据建议包括：`source_id`、题名、作者/发布机构、来源类型、发布日期/版本、章节页码、原始URL/DOI、使用许可说明、抓取/导入日期、有效状态、内容指纹。更新时保留版本，不静默覆盖旧证据。

资料文本按“内容数据”处理，不执行其中任何指令。检索服务端实行来源白名单、内容大小限制与工具权限控制。来源无法核验时不进入可回答资料集。

## 6. 验收与效果指标

正式指标阈值须等首批资料、问题类型和专业评测集确定后再冻结；在此之前只定义口径，不虚构准确率目标。

| 维度 | 建议口径 | 失败例 |
|---|---|---|
| 检索相关性 | 标准问题的关键依据是否进入Top-k | 找到同主题但不回答问题的文章 |
| 来源合规 | 检索和引用是否全部来自允许目录 | Agent绕到开放互联网或引用未入库来源 |
| 引用准确 | 引用链接/版本/章节是否真实对应展示段落 | 链接存在但引文不支持回答 |
| 回答有据 | 每条重要主张能否由引用片段支持 | 模型添加材料中没有的诊断建议 |
| 拒答适当 | 无依据、冲突或越界问题是否停止并解释 | 无资料时编答案或不必要拒答 |
| Agent可控 | 工具、重查次数、终止条件与审计状态符合约定 | 无限重试、工具越权、失败被包装成成功 |
| 体验与成本 | 完成时长、失败率、请求量/费用及用户是否能定位出处 | 答案过长、超时、调用成本不可解释 |

测试集需同时含：可答题、无依据题、含糊题、过期资料/版本冲突题、越界患者问题、提示注入文本、检索工具失败。由影像专业人员审核知识问题及参考答案；个人AI复核不是临床专家背书。

## 7. 依赖、阶段门和角色分工

| 顺序 | 阶段与产出 | 主要依赖/决策门 | 主要责任 |
|---|---|---|---|
| 1 | 问题范围与用户任务：问题分类、禁止事项、界面入口 | 先确认助手的回答边界；不得以“医生什么都能问”作为需求 | 产品主导；领域人员审阅 |
| 2 | 来源目录与许可清单 | 未确认许可和维护人，不导入教材/全文或批量抓取 | 产品/内容治理核查；必要时法务/版权顾问确认 |
| 3 | RAG基线：资料解析、元数据、分段、检索、引用 | 先用小批授权资料建可复现基线；决定关键词/混合/向量方案需看测试结果 | 研发实现；产品提供检索问题；QA核对出处 |
| 4 | 有界Agent流程与工具契约 | 在RAG检索基线可用后，再决定哪些环节需动态选择；明确动作白名单、单次重查上限和停止条件 | 产品定义策略；研发实现状态/工具；QA测越权和失败 |
| 5 | 评测、专业复核与迭代 | 专家参考答案和留出问题就绪；阈值和风险可接受后才进入演示验收 | QA组织；领域人员审阅；产品决定是否接受缺口 |
| 6 | 集成演示与交付说明 | 不与报告检查结果混淆；清楚标“资料范围/版本/局限/非诊疗用途” | 设计/研发/产品共同交付 |

当前角色由用户与AI协作模拟，不是真实公司部门或外部医学评审。没有实际专家审阅前，验证范围仅为技术流程与合成/公开许可资料演示。

## 9. 产品分工与实现依据

产品角色定义知识查询任务、来源范围、用户状态与验收口径；研发实现检索、有限动作、预算和引用校验；测试按可答/无依据/工具失败/越权/旧输入等情况核验；领域专家负责专业内容质量，当前尚未参与。上述产品、研发和测试工作由维护者与AI协作完成，不等于真实公司团队或外部专业评审。

设计依据是用户需求、现有项目结构、出版社资料与本轮验证。
