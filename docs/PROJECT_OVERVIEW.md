# 项目设计与关键决策

## 问题定义

影像报告的“影像所见”和“诊断意见”可能对同一对象使用不一致的侧别、尺寸或肯否表达。本项目探索在报告提交前增加文本一致性自检步骤：定位两段文字中的差异，提供证据，由使用者核对并修改。

场景来自影像设备行业接触与工作流观察，尚未通过正式医生访谈、医院试点或临床研究验证。当前以合成文本检查有限范围内的功能行为。

## 构建过程

1. **定义任务与边界**：输入限定为两段报告文本，输出为需人工核对的候选。文本差异无法证明哪段医学上正确，因此不自动修改或签发报告。
2. **验证单模块流程**：先实现左右表达检查，明确证据区间、无法比较状态及基本交互，再扩展到单值尺寸和明确肯否。
3. **形成操作闭环**：将规则选择、证据查看、人工修改复检、反馈、历史记录与导出连成一条任务路径；区分输入版本与结果归属。
4. **引入可选模型复核**：先观察规则能力，再按需请求模型。通过结构、类别、原文证据及输入身份校验后接纳候选，模型失败时保留规则结果。
5. **固定案例并迭代**：保存合成输入与预期、运行实现、记录差异。修复明确历史、多对象误配和尺寸格式等问题；旧案例、标签与结果保持可追溯。
6. **整理独立交付**：从允许清单构建可运行副本，核对文件与校验值，再公开代码、设计、流程图及合成数据。

项目使用 AI 辅助整理方案、实现代码和执行技术验证；范围选择、操作反馈与发布范围由项目维护者确认。角色审查为 AI 模拟，尚无外部独立临床评审。

## 关键决策

### 规则优先与按需模型复核

单位换算和受限明确表达可以采用可复现规则。复杂语义交由可选模型提出候选，同时引入等待、费用和不确定性。分开执行可保留规则可用性，也便于观察模型是否带来新增发现。

### 原文证据与保守合并

每个提示关联两段输入中的证据区间。模型类别、证据和规则候选严格匹配时才合并；局部重叠不直接视为同一问题，模型无候选也不删除已有规则提示。两种来源一致不等于医学结论已确认。

### 明确覆盖范围

同一位置存在多个对象时，不能删除模糊片段后假定剩余对象唯一。范围、近似、多径、历史与测量口径不明时，系统说明跳过原因。前后提示数量仅在同一任务及兼容检查条件下比较；零提示不等于完整覆盖。

### 模型分类失败后的展示策略

2026-10-20 数量案例中，规则无法可靠比较；模型发现“一枚/三枚”的差异，却将其归为肯否冲突。系统保留该失败及原始类别，将 AI 独有新增候选展示为“文本不一致候选，类别待核对”。修复通过已保存结果离线回放及明确 mock 页面检查验证，没有为获得更好结果重新调用模型。产品兜底不代表原模型分类已被纠正。

### 当前暂不使用 RAG Agent 或模型微调

当前任务只比较用户输入的两段文本，步骤固定，现有样本又是合成开发案例。RAG要解决的外部资料检索需求尚未得到验证，Agent的动态多步决策也不是当前流程所需；模型微调则缺少有授权、具代表性并经领域标注的训练与独立评测数据。详细的适用场景、引入条件和验收要求见[AI技术选型与范围说明](AI_TECH_DECISIONS.md)。

## 验证与后续方向

规则验收、自动化测试、真实模型开发对照和模拟页面检查分别记录，详细结果见 [ACCEPTANCE.md](ACCEPTANCE.md)。合成案例由已知实现后的定向设计产生，无法支持临床效果或外部泛化结论。

后续优先验证实际报告工作流与使用价值，建立独立标注和保留数据，扩展复杂表达并评估误报/漏检，再根据实际接入条件讨论数据保存、权限和系统集成。
